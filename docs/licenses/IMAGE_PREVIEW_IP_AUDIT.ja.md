## 1. 概要と目的

Cuddle では、原本保護型ファイルワークベンチとしての利便性を高めるため、プレビュータブにおいて一般的な Web 画像（PNG, JPEG, SVG 等）のみならず、一眼カメラの **RAW 形式**、スマートフォン写真の **HEIC / HEIF**、印刷・DTP の **TIFF / PSD**、CG 用の **HDR** などのプレビュー表示をサポートしています。

しかし、マルチメディア・画像圧縮技術の領域には、**複雑な特許プール（Patent Pools）、ライセンス料（ロイヤリティ）請求リスク、および GPL/LGPL 等のコピーレフトライセンス汚染リスク** が存在します。

本文書は、全機能追加が完了した後の最終段階で実施される「包括的ライセンス監査」において、本画像プレビュー実装が **Cuddle の MIT ライセンス（極めて寛容な商用利用・再配布許諾）と完全に整合し、かつ特許侵害リスクを回避できていること** を客観的に照合・立証できるよう、技術的根拠・法的検討結果・監査チェックリストをまとめたものです。

## 3. HEIC / HEIF における「外部ツール委譲方式」の法的有効性

### 3.1 なぜ直接静的リンク（Static Link）してはならないのか
もし Cuddle の Rust バックエンドに `libheif-sys` などを直接リンクして HEIC デコード機能をアプリ内に内包した場合：
1. **特許ロイヤリティの請求主体となるリスク：**
   パテントプール（HEVC Advance 等）の規約上、HEVC デコーダを組み込んだ商用・非商用の配布物に対してライセンス料請求やコンプライアンス調査が行われる恐れがある。
2. **LGPLv3 / GPL ライセンス感染のリスク：**
   `libheif` の LGPLv3 条件（動的リンク義務、改変バイナリの差し替え可能性の保証、リバースエンジニアリング制限条項の無効化）を、単一バイナリ配布が一般的なデスクトップ環境で満たすことが困難になる。

### 3.2 外部ツール委譲（Dynamic CLI Delegation）による法的保護
Cuddle が採用した設計：
* **コードベースの完全な分離（Loose Coupling）：**
  Cuddle のソースコードおよび配布バイナリには、HEVC をデコードするコードやバイナリは 1 バイトも含まれていません。
* **オペレーティングシステム（OS）への責任分離：**
  変換処理は、ユーザーが自身でインストールした外部バイナリ（`/usr/bin/magick` または `/usr/bin/ffmpeg`）を子プロセス（`std::process::Command`）として呼び出すだけです。Linux ディストリビューション（Arch, Ubuntu, Fedora 等）やユーザー自身の管理責任下にあるツールを利用する形態であるため、Cuddle の開発者・配布者が「デコーダの頒布者」として責任を問われることは法的に成立しません。
* **Linux Landlock LSM による原本保護・セキュリティ担保：**
  外部プロセスの実行時は、カーネルレベルのアクセス制限（読み取り専用パス限定・`TMPDIR` 隔離）を適用し、原本ファイルの改変・漏洩を防止しています。

## 4. 包括的ライセンス監査（Comprehensive License Audit）実施時のチェックリスト

全機能開発が完了し、最終監査を実施する担当者は、以下の項目を順に確認してください：

### ☑ チェック 1: 配布バイナリの静的リンク検査（HEVC / GPL の混入ゼロ確認）
ビルドされた Cuddle の ELF バイナリに対してシンボル検査を実施し、HEVC デコーダや GPL ライブラリが静的リンクされていないことを確認する。
```bash
# バイナリシンボルの検査
nm -D src-tauri/target/release/cuddle | grep -iE "heif|de265|hevc|x265"
# 期待値: 何も出力されないこと（0件）

# 動的リンク共有ライブラリの検査
ldd src-tauri/target/release/cuddle | grep -iE "heif|de265|x265"
# 期待値: 何も出力されないこと（0件）
```

### ☑ チェック 2: 使用 Rust クレートのライセンス監査
画像プレビューおよびメタデータ抽出で使用しているクレートのライセンスを確認する。
```bash
cargo deny check licenses
```
* **確認対象クレート：**
  * `kamadak-exif`: **BSD-2-Clause**（MIT 互換、商用利用・再配布自由）
  * `base64`: **MIT / Apache-2.0**（デュアルライセンス、完全適合）
  * `serde`, `serde_json`: **MIT / Apache-2.0**（完全適合）

### ☑ チェック 3: 外部ツール未インストール環境での安全動作確認
ImageMagick や FFmpeg が存在しないクリーンな環境（Docker コンテナ等）において、HEIC ファイルをプレビューした際に：
1. アプリがクラッシュしないこと。
2. 不当な変換処理を試みてフリーズしないこと。
3. `「この形式 (HEIC) のプレビューには外部ツール (ImageMagick または FFmpeg) が必要です」` というガイダンスが正常に表示されること。

### ☑ チェック 4: カメラ RAW の埋め込み JPEG 抽出の完全性
カメラ RAW（CR2, NEF, ARW 等）が、外部現像ライブラリ（libraw 等）をリンクすることなく、内蔵プレビュー JPEG のパースのみで安全に表示されることを確認する。
